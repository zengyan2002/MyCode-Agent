# 审查当前代码变更

默认审查当前工作区的 Git 变更。先确认当前目录是否是 Git 仓库，再读取 staged 和 unstaged diff。参数只是额外关注点，不替代默认审查范围。

重点检查：

1. 逻辑正确性和边界条件。
2. 可能造成真实影响的安全问题。
3. 性能退化。
4. 代码风格和项目现有约定是否一致。
5. 可维护性和遗漏的测试。

只报告由当前变更引入、开发者可以直接处理的问题。按以下等级排列：

- Critical：必须修复，否则会造成严重错误、数据损失或明确安全风险。
- Warning：建议修复，当前实现存在可复现的问题或明显维护风险。
- Info：可以改进，但不影响当前功能正确性。

每个问题要说明文件位置、触发条件、实际后果和建议修改方向。没有发现问题时明确说明。当前目录不是 Git 仓库或没有变更时，也要明确说明，不要编造审查结论。
